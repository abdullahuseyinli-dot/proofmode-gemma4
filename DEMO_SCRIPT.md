# ProofMode judging demo — 3 minutes

## Before recording

- Run `launch-proofmode.cmd` and keep Gemma warm.
- Open two app windows if demonstrating peer roles.
- Start with a fresh local database or clearly label existing data as seeded demo history.
- Never describe the research-preparation pass as model training.

## Script

**0:00–0:20 — Thesis**

“Most study assistants answer questions. ProofMode schedules proof, not promises. It replans only when learning evidence changes.”

Show the local Gemma 4 E4B indicator and the target-mark slider.

**0:20–0:50 — Minimal onboarding**

Set 85%. Upload a note image and `.ics` calendar, or use the labelled demo files. Click **Build my autopilot plan**. Point out the detected exam, risk-weighted topic graph and real free-time blocks.

**0:50–1:15 — Behavioural recovery**

Open **Focus + Proof**. Mark a session missed, choose “overwhelmed,” and show Gemma's native function call selecting a seven-minute rescue. Say that constant notifications become noise, so interventions are event-triggered.

**1:15–1:50 — Learning Receipt**

Generate the check. Answer one MCQ, provide an open explanation and confidence, and upload worked notes. Submit. Show Knowledge, Depth, Calibration and Evidence separately, then return to the calendar and show it changed.

**1:50–2:20 — Verified Tutor**

Ask a technical question. Show the bounded research pack, inline `[S#]` citations and separate verifier. Explain that unsupported claims are held instead of shown.

**2:20–2:45 — Teach-Back and competition**

Show pre-question → peer explanation → new transfer question. Reveal Teaching Impact and ProofScore. Emphasise that hours, messages and copied/repeated answers do not improve the public score.

**2:45–3:00 — Proof of Gemma integration**

Open **AI Audit**. Point to the E4B model, image/text modality, structured assessment, function call and latency. Finish: “ProofMode turns a calendar intention into evidence, recovery and replanning—all locally with Gemma 4.”
